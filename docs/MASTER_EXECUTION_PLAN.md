# CivilMind AI — Mandatory Master Execution Plan

**Status: Binding.** Every worker must read this file before coding. It defines the official access model, 14-phase roadmap, sprint order, completion rules and persistent command `توسعه`.

## 1. Permanent Access Rules

### Guest — free without login
- All official regulations and approved public sources
- Official exam booklets and questions
- Initial keys, final keys and officially published descriptive answers
- Discipline and qualification selection and filtering
- Public search, source metadata, editions and official links
- Public updates, public heat maps, Premium previews
- Small Ask CivilMind AI demo and limited voice-to-text when available

### Free registered user
Everything available to guests, plus profile, bookmarks, continue reading, history, basic progress, official practice exams, limited AI and limited voice input.

### Premium user
Premium unlocks intelligence, not documents: advanced AI chat, cited question analysis, Copilot, tutor, adaptive planner, weakness analytics, AI exam generation, smart summaries, document/PDF intelligence, voice-to-voice, oral exams, knowledge graph, personalized memory and evidence-based prediction.

### Non-negotiable rule
Official regulations, official questions, official keys, official descriptive guides and discipline/qualification filtering must never require Premium.

### Content separation
Always distinguish official source, official booklet, initial key, final key, official descriptive answer, CivilMind AI analysis, AI-generated question and AI prediction. AI output must never appear official.

### Trust rule
Use verified sources and show document, edition, chapter, clause and page where known. Never invent citations, statistics, pass rates, live counters, testimonials or certainty.

## 4. Definition of Done for Every Sprint

A sprint is complete only when:
1. its approved scope is complete;
2. required frontend and backend are connected;
3. the real user flow works end-to-end;
4. access rules are correct;
5. lint passes;
6. relevant tests pass;
7. production build passes;
8. sprint-caused errors are fixed;
9. `docs/CHANGELOG.md` is updated;
10. changes are committed and pushed;
11. a working preview is deployed or updated;
12. the preview is verified in Cloud Browser;
13. a screenshot is supplied when UI changed;
14. the next sprint is recorded and starts immediately without approval.

An audit, plan, browser tab, query, helper, schema, backend function or disconnected component alone is not a completed sprint.

---

## 5. Continuous Execution Rule

After completing a sprint, report branch, commit SHA, preview URL, changed files and checks briefly, then immediately begin the next sprint. Do not ask whether to continue.

Stopping is allowed only after all sprints are complete or a real blocker exists. Real blockers are missing credentials, inaccessible required infrastructure, an irreversible owner decision or an unavailable external dependency with no safe alternative. Build errors, test failures and refactoring are not blockers; fix them.

---

## 6. Persistent Command `توسعه`

Whenever the user sends only `توسعه`, the worker must:

1. read this file completely;
2. read `docs/CHANGELOG.md`;
3. inspect latest pushed commits;
4. find the first genuinely incomplete sprint;
5. resume from the exact incomplete task;
6. complete at least one full sprint end-to-end;
7. run lint, tests and production build;
8. fix failures;
9. commit and push;
10. deploy/update and verify Preview;
11. update Changelog;
12. report completed work only;
13. immediately continue to the next sprint without waiting for approval.

Do not answer `توسعه` with confirmation, planning, audit results, browser status, criteria registration, existing-UI descriptions or partial progress. The first response is allowed only after at least one complete sprint is pushed, unless a real blocker exists.

### Low-time or low-token rule
Do not falsely mark a sprint complete. Finish and push the current safe atomic change, update Changelog with phase, sprint, completed items, exact incomplete item, next file/flow, branch, commit SHA and preview URL, then resume from that exact point on the next `توسعه`.
