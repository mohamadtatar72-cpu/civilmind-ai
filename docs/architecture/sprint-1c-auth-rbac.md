# Sprint 1C — احراز هویت و کنترل دسترسی

## هدف

این Sprint هویت کاربران، نقش‌های `free`، `premium` و `admin`، پایه اشتراک، گزارش رویدادهای حساس و صف تأیید تغییرات منابع رسمی را به CivilMind اضافه می‌کند.

## تقسیم مسئولیت

- **Clerk:** ثبت‌نام، ورود، Session، تأیید ایمیل و صدور JWT.
- **Convex:** نگهداری پروفایل کاربردی، نقش، وضعیت حساب، اشتراک، Audit Log و اجرای تمام مجوزهای حساس.
- **Next.js:** نمایش رابط کاربری و محافظت اولیه مسیرها با `proxy.ts`.

محافظت مسیر در Next.js تنها لایه تجربه کاربری است. مرز امنیتی واقعی در توابع Convex قرار دارد.

## مدل نقش‌ها

- `free`: دسترسی پایه و سهمیه محدود آینده.
- `premium`: قابلیت‌های حرفه‌ای و سهمیه بیشتر آینده.
- `admin`: مدیریت کاربران، Audit Log و تصمیم نهایی منابع رسمی.

نقش از آرگومان مرورگر، Local Storage یا Clerk public metadata خوانده نمی‌شود. نقش معتبر فقط رکورد `users` در Convex است.

## Bootstrap مدیر اولیه

تابع `claimInitialAdmin` فقط زمانی موفق می‌شود که:

1. `ADMIN_BOOTSTRAP_EMAIL` در محیط Convex تنظیم شده باشد.
2. ایمیل تأییدشده هویت با مقدار Bootstrap برابر باشد.
3. هیچ مدیر دیگری قبلاً ایجاد نشده باشد.
4. وضعیت حساب فعال باشد.

این مسیر برای ایجاد اولین مدیر است و پس از آن مدیریت نقش‌ها فقط توسط مدیر موجود انجام می‌شود.

## صف تأیید منابع

جدول `sourceChangeProposals` تغییرات کشف‌شده آینده را با گزارش امنیتی، Hash و سطح ریسک نگهداری می‌کند. هیچ تابع عمومی برای ایجاد Proposal وجود ندارد؛ ایجاد فقط از طریق `internalMutation` انجام می‌شود. تأیید یا رد نیز فقط توسط مدیر ممکن است.

Sprint 1C موتور Scraping یا انتشار خودکار را فعال نمی‌کند.
